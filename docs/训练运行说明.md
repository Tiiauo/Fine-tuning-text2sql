# 第 3～7 步脚本运行说明

在项目根目录运行。以下假定模型与原始数据已由下载脚本保存到 `/data/text2sql`；所有目录都应位于持久化数据盘。

## 脚本与步骤

| 步骤 | 脚本 | 输出 |
|---|---|---|
| 3：清洗、校验、去重 | `scripts/prepare_data.py` | 清洗后三个 split、隔离记录、来源哈希；可选 SeSQL SQLite |
| 4：专项样本 | `scripts/generate_special.py` | 字典、指标、澄清、安全等可执行虚拟样本和独立数据库 |
| 5：固定数据划分 | `scripts/build_dataset.py` | 冻结的 JSONL、Schema 隔离检查、数据及数据库 SHA256 |
| 6：基线推理 | `scripts/predict.py` | 可恢复的逐条模型输出及运行元信息 |
| 6：SQL 与行为评测 | `scripts/evaluate.py` | JSON 指标及逐条错误明细 |
| 7：QLoRA＋SFT | `scripts/train_qlora.py` | adapter、完整中间检查点、训练状态与损失记录 |
| 10：最终对比验收 | `scripts/compare_reports.py` | 同条件校验、阈值结论、JSON/Markdown 对比与逐条变化 |

第 1～11 步的完整执行顺序、阈值约定及最终测试命令见 [微调执行流程.md](微调执行流程.md)。

## 依赖环境

下载继续使用 `.venv-download`。数据处理只需要 Python 3.11/3.12 和 `requirements-data.txt`，不需要 GPU。建议创建单独训练环境，避免下载用的新版 huggingface_hub 与固定 Transformers 版本冲突。

```bash
python3.11 -m venv .venv-train
source .venv-train/bin/activate

# 云服务器先选择带兼容驱动的 PyTorch 2.8.0/CUDA 镜像，
# 或根据该服务器的 CUDA/驱动条件安装对应 CUDA 版 torch 2.8.0。
# 确认不是 CPU-only 安装：
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"

python -m pip install -r requirements-train.txt
python -m pip check
```

`requirements-train.txt` 固定了 Transformers 4.57.1、TRL 0.24.0、PEFT 0.17.1 等接口版本，并约束 torch 2.8.0。已做 Python 3.11/Linux 依赖解析；CUDA、bitsandbytes 与实际 GPU 的运行兼容性仍需云端验证。不要把本机 Windows 上的数据测试当作 GPU 训练验证。

若暂时只运行步骤 3～5 或执行评测，可先仅安装：

```bash
python -m pip install -r requirements-data.txt
```

## 3：准备数据

```bash
# 首轮仅 CSpider
python scripts/prepare_data.py --assets-dir /data/text2sql

# 若已下载 SeSQL，选择新的输出版本，不覆盖上一版
python scripts/prepare_data.py --assets-dir /data/text2sql \
  --include-sesql --output-dir /data/text2sql/data/prepared-v2
```

默认输出 `/data/text2sql/data/prepared/`。输出目录必须是 assets-dir 内的新目录，以便保存可迁移的数据库相对路径。原始数据只读；SeSQL 重建库保存到新 prepared 目录下。SeSQL 数值内容不在 Python 中强制转型，采用 SQLite 数值 affinity；特殊标识符未引用导致无法执行的 SQL 会隔离，不自动改写标准答案。

检查 `manifest.json` 和 `rejected.jsonl`。脚本验证物理 Schema、已声明主外键、参考 SQL 可执行性，过滤同库同问题同 SQL 的重复记录；相同 SQL 出现在不同 Schema 下不会被全局删除。混合数据时，若 Schema 出现在多个 split，保留测试优先、开发其次，隔离较低优先级记录，不将 held-out 数据移动到训练集。

SQL 默认限时 2 秒、结果最多 10000 行；超限样本也会隔离，属于本轮资源策略，不等于标注错误。通过 `--timeout` 调整超时。成功执行不能证明问题和 SQL 语义一致，仍须人工抽审。该清洗后测试集不是原始官方榜单评测集。

## 4：生成专项样本

```bash
python scripts/generate_special.py --assets-dir /data/text2sql
```

默认生成 32/8/8 个训练、开发、测试数据库，每库 18 条样本，覆盖字段匹配、别名字典、指标定义变化、去重/分子分母、关联、时间范围、默认规则、澄清后补充、写操作/危险函数/权限拒绝。专项数据输出 `/data/text2sql/data/special/`。

这些是可复现的虚拟业务模板种子数据，需要抽审和后续扩充。各 split 的物理 Schema 不同，但共享生成模板；专项测试分数不能证明真实业务泛化。仅支持本期 SQLite 与表级权限，不声称实现了生产系统的行列级权限。

## 5：冻结数据版本

```bash
python scripts/build_dataset.py --assets-dir /data/text2sql \
  --special-dir /data/text2sql/data/special

# 如果使用了 prepared-v2：
# 加 --prepared-dir /data/text2sql/data/prepared-v2
```

默认输出 `/data/text2sql/data/sft-v1/`。包含 `train.jsonl`、`dev.jsonl`、`test.jsonl` 与 `manifest.json`。文件及 SQLite 数据库哈希被记录；后续脚本发现冻结文件或评测数据库发生变化会报错。

记录包括数据源、split、唯一 ID、物理 Schema 指纹、数据库相对路径、问题、上下文、目标行为、SQL、排序要求与能力标签。模型回答协议统一为以下 JSON 三选一：

```json
{"action":"sql","sql":"SELECT ..."}
{"action":"clarify","question":"请提供统计的起止日期。"}
{"action":"refuse","reason":"当前没有该表的访问权限。"}
```

没有随机按行重新划分已有官方数据；不把 test 合并入 train。后续修订数据使用新的输出版本，旧版本保留。

## 6：建立基线并评测

```bash
python scripts/predict.py --model-dir /data/text2sql/models/Qwen3-8B \
  --data-file /data/text2sql/data/sft-v1/dev.jsonl \
  --output-file /data/text2sql/predictions/base-dev.jsonl

python scripts/evaluate.py --assets-dir /data/text2sql \
  --data-file /data/text2sql/data/sft-v1/dev.jsonl \
  --predictions /data/text2sql/predictions/base-dev.jsonl \
  --output-dir /data/text2sql/reports/base-dev
```

推理固定单卡、4-bit、非思考模板、贪心解码。训练与基线使用同一个系统提示和回答协议。Schema 超出输入上限时记录错误而不截断；`--max-input-tokens` 和 `--max-new-tokens` 可调整。模型与 tokenizer、分片做 SHA256 指纹计算，首次运行会读取完整权重文件，增加少量启动 I/O。

可用 `--limit 20` 做调用冒烟检查；这会产生不完整预测，评测仍以整个指定 split 为分母并显示 coverage，不可把这种结果当作完整基线。预测中断后，加 `--resume` 使用完全相同的数据、模型、adapter 和生成配置继续；不接受损坏的半行 JSON 或重复 ID。

如另行准备了 XiYanSQL 本地模型，可用 `--prompt-style xiyan` 生成 SQL 子集对照。该模式只处理 SQL 目标，采用模型卡的中文 Schema/evidence 提示布局；对完整行为测试集的 coverage 会较低，不能用它证明模型具备澄清/拒绝能力。

评测包含 SQL 执行结果匹配、action accuracy、澄清/拒绝 action precision 与 recall，以及按来源、标签分类的明细。重复行、列顺序有意义；有顶层 ORDER BY 时检查行顺序，无 ORDER BY 时按多重集合语义比较，数值采用固定容差。列别名不同可接受，但列位置必须一致。单库结果一致、尤其两个空结果，不能证明 SQL 等价；报告单独记录空结果匹配。澄清关键词覆盖仅为辅助指标，具体是否问对仍需抽审。

当前版本还记录测试数据与数据库哈希、评分代码及运行参数、预测元信息、逐条明细哈希和成功生成样本的 mean/p50/p95 延迟。最终对比需要这些信息；旧版缺少元信息的预测和报告不能直接用于最终验收，须重新生成。

SQLite 执行使用只读连接、authorizer、禁用扩展、长度与行数限制、执行进度超时；禁止写入、ATTACH、PRAGMA、危险函数及不允许访问的表。这里是本地受限评测执行器，不是生产环境的完整沙箱或权限系统。

基线报告生成后，结合项目要求冻结量化验收阈值并记录。脚本不编造尚未测得的目标准确率；最终 test 只用于最终验收，开发调参始终使用 dev。

## 7：QLoRA＋SFT 脚本

先用少量步数检查云端环境，单独使用一个 smoke 输出目录：

```bash
python scripts/train_qlora.py --model-dir /data/text2sql/models/Qwen3-8B \
  --data-dir /data/text2sql/data/sft-v1 \
  --output-dir /data/text2sql/runs/smoke-v1 \
  --max-steps 4 --checkpoint-steps 2 --drop-overlong
```

上述命令包含实际训练，仅在云服务器准备好后执行。本轮代码编写没有执行它。

默认总长度 4096、micro-batch 1、梯度累积 16、LoRA rank 16、学习率 2e-4、2 epochs。均为起跑配置，不是已验证的最优参数。训练前会校验冻结数据、模型和 tokenizer 指纹，检查官方非思考模板的 prompt/completion 边界。只对回答部分计算损失，不将用户问题或 Schema 当作监督目标；packing 关闭。

默认发现超长样本即停止。显式传 `--drop-overlong` 才整条排除，并写入 `tokenization_report.json`；不会从右侧截断标准 SQL。正式运行前检查排除数量与来源，避免把所有复杂查询都过滤掉。云端需要足够 CPU 内存保存数据和 token，不能只看 GPU 显存。

正式运行示例及日志保存：

```bash
mkdir -p /data/text2sql/logs
set -o pipefail
python scripts/train_qlora.py --model-dir /data/text2sql/models/Qwen3-8B \
  --data-dir /data/text2sql/data/sft-v1 \
  --output-dir /data/text2sql/runs/sft-v1 --drop-overlong \
  2>&1 | tee /data/text2sql/logs/sft-v1.log
```

默认每 100 steps 保存并计算 dev loss，保留最近两个完整中间检查点；`--checkpoint-steps` 可调整。恢复时指定实际存在的 checkpoint，训练配置和数据须与原运行相同：

```bash
python scripts/train_qlora.py --model-dir /data/text2sql/models/Qwen3-8B \
  --data-dir /data/text2sql/data/sft-v1 \
  --output-dir /data/text2sql/runs/sft-v1 --drop-overlong \
  --resume-from-checkpoint /data/text2sql/runs/sft-v1/checkpoint-100
```

`adapter/` 是最终推理产物，单独的 adapter 不是含优化器状态的训练检查点。输出目录存在而未指定恢复时会停止，避免覆盖。初始化失败、且没有有效检查点时，保留故障目录并换新输出路径重试。最终保存训练指标、GPU 峰值 allocated 显存和 dev loss；dev loss 不能代替执行正确率。

恢复前会检查训练状态、优化器、调度器、随机状态和 adapter 文件是否齐全；缺少任一项都会停止，不把不完整目录当作可复现的完整检查点。

后续训练完成后，复用相同推理与评测脚本，加 `--adapter-dir /data/text2sql/runs/sft-v1/adapter`，写入新的预测与报告路径，与基线比较。

## 验证范围

本地测试覆盖小型 SQLite 端到端清洗/专项/冻结/评测、只读和权限约束、重复行与排序、数据哈希防变更、Schema 防泄漏、SeSQL 字符串保留及回答损失掩码。另实际处理了作者完整 CSpider＋SeSQL，并使用真实 Qwen tokenizer 检查非思考模板。

尚未运行完整模型基线推理、CUDA 训练、GPU 峰值显存或训练断点恢复。这些必须在租用的服务器上通过短程训练与恢复检查确认，再进行正式训练。没有加入 DPO 或 GRPO。
