# Text2SQL 微调执行流程

更新日期：2026-10-26。

主路线：Qwen3-8B 非思考模式 → QLoRA＋SFT → 同口径执行及行为评测 → 对比验收。首期不增加 DPO／GRPO。

本流程在云服务器逐步执行，不是自动启动整套任务的脚本。本轮仅编写代码及做本地验证，没有启动云端训练。

## 目录与执行约定

将项目文件上传到服务器。以下命令在 Bash 中执行，先将两条路径改成真实路径：

```bash
PROJECT_DIR=/data/text2sql-project
ASSETS_DIR=/data/text2sql
cd "$PROJECT_DIR"
mkdir -p "$ASSETS_DIR/logs"
set -o pipefail
```

- `PROJECT_DIR`：本项目脚本、依赖与配置所在目录。
- `ASSETS_DIR`：持久化数据盘，保存模型、数据、检查点、预测及报告。
- 数据与报告目录按版本新建。脚本拒绝覆盖已有清洗、冻结或报告目录；预测和训练使用明确的恢复参数。
- 推荐先按单卡 NVIDIA 24GB、Python 3.11、足够 CPU 内存及持久化磁盘规划。CPU 内存与磁盘建议分别从 32GB、50GB 空闲空间起步，实际需求通过试跑确认。
- 完整型号、驱动及 CUDA 配置确定后再安装 GPU 依赖，不能仅凭显存容量判断兼容性。

## 微调产物的存储路径

以下按 `ASSETS_DIR=/data/text2sql` 和本流程的命令列出。更改 `ASSETS_DIR` 时，统一替换路径前缀；脚本通过 `--assets-dir`、`--output-dir`、`--output-file` 等参数控制位置。

| 阶段／产物 | 存储路径 | 用途与保留要求 |
|---|---|---|
| 原始底座模型 | `/data/text2sql/models/Qwen3-8B/` | 权重、配置、tokenizer 和下载信息；训练及加载 adapter 时需要 |
| 下载原包 | `/data/text2sql/downloads/full_CSpider.zip`、可选 `SeSQL.zip` | 下载校验与复核；手工上传的包保持在 `--cspider-archive` 指定位置 |
| 原始数据 | `/data/text2sql/data/raw/cspider/`、可选 `sesql/` | 只读输入，保留官方划分；CSpider 的 `database/` 和 `test_database/` 是可执行数据库 |
| 清洗数据及隔离记录 | `/data/text2sql/data/prepared/` | `train/dev/test.jsonl`、`manifest.json`、`rejected.jsonl`；若按示例加入 SeSQL，则输出到 `prepared-v2/` |
| SeSQL 重建库 | `/data/text2sql/data/prepared-v2/databases/sesql/<db_id>/<db_id>.sqlite` | 仅启用 SeSQL 时生成，随对应 prepared 版本保留 |
| 专项数据 | `/data/text2sql/data/special/` | 三个 split、manifest 及 `databases/<标识>.sqlite`，用于专项训练和行为评测 |
| 冻结训练数据 | `/data/text2sql/data/sft-v1/` | 三个 JSONL 与 manifest；训练、基线及验收引用这一冻结版本 |
| 验收阈值 | `/data/text2sql/acceptance-v1.json`、`acceptance-v1.sha256` | 在正式训练前填写并冻结，与最终报告一起保留 |
| 短程试训 | `/data/text2sql/runs/smoke-v1/` | 试训配置、检查点、adapter 与指标；独立于正式运行 |
| 正式训练 | `/data/text2sql/runs/sft-v1/` | 见下方目录说明，每次正式实验使用新版本目录 |
| 控制台日志 | `/data/text2sql/logs/smoke-v1.log`、`smoke-resume.log`、`sft-v1.log` | 由命令中的 `tee` 写入，记录启动、进度及错误；不使用 `tee` 时不会自动生成这些文件 |
| 模型预测 | `/data/text2sql/predictions/base-dev.jsonl`、`sft-dev.jsonl`、`base-test.jsonl`、`sft-test.jsonl` | 每条预测、耗时；相邻的 `*.jsonl.meta.json` 保存模型及生成条件，须一起保留 |
| 单模型评测 | `/data/text2sql/reports/base-dev/`、`sft-dev/`、`base-test/`、`sft-test/` | 每个目录包含 `report.json`、`details.jsonl` |
| 最终验收 | `/data/text2sql/reports/acceptance-v1/` | `comparison.md`、`comparison.json`、`changes.jsonl`，保存结论与改善／回退记录 |

正式训练目录的关键文件：

```text
/data/text2sql/runs/sft-v1/
├── run_config.json                 # 本次参数、模型与数据指纹、依赖版本
├── tokenization_report.json        # 保留数量、超长排除记录
├── checkpoint-N/                   # 默认每 100 steps 保存一次
│   ├── adapter_model.safetensors
│   ├── adapter_config.json
│   ├── optimizer.pt
│   ├── scheduler.pt
│   ├── rng_state.pth
│   └── trainer_state.json          # 训练步数及 log_history；还可能包含 tokenizer 等文件
├── adapter/                        # 正常完成训练后的最终推理产物
│   ├── adapter_model.safetensors
│   ├── adapter_config.json
│   └── ...                        # tokenizer 文件
├── trainer_state.json              # 正常完成后的训练状态与日志历史
├── train_results.json              # 训练耗时、吞吐、峰值 allocated 显存、GPU 信息
└── evaluation_loss.json            # 正常完成后的开发集 loss
```

- `run_config.json` 和 tokenization 报告在模型加载／训练前写入；目录出现这两个文件不代表训练成功。最终 adapter 和结果文件只有走到相应保存步骤才会生成。
- 默认只保留最近两个完整 `checkpoint-N`。需要长期保留的检查点应另行备份；`adapter/` 不含优化器等恢复状态，也不包含完整底座权重。
- 虽然配置指定了运行目录内的 `logs/`，当前 `report_to=none` 不保证生成 TensorBoard 文件；以外部 `tee` 日志、`trainer_state.json` 和指标 JSON 为准。
- 冻结 JSONL 中的 `db_path` 相对 `ASSETS_DIR`，数据库并未复制进 `sft-v1/`。不要只保留冻结 JSONL 后删除原始、prepared 或 special 中被引用的 SQLite 文件。
- 所有上述产物应存到持久化盘，并在释放服务器前备份。Git 仓库只保存代码、配置模板、测试和文档；提交仓库不等于备份训练产物。
- 恢复训练还会检查原参数、路径、模型和数据指纹。迁移服务器时需保留相同路径／配置；重新开始的实验则使用新的输出版本。

## 1．确认服务器与 GPU

```bash
nvidia-smi
python3.11 --version
df -h "$ASSETS_DIR"
```

确认 GPU 可见、驱动可用、数据盘可写。不要把临时系统盘作为唯一的模型和检查点存储位置。

## 2．下载模型与数据

```bash
python3.11 -m venv .venv-download
source .venv-download/bin/activate
python -m pip install -r requirements-download.txt
python scripts/download_assets.py --output-dir "$ASSETS_DIR"
deactivate
```

默认下载 ModelScope 的 Qwen3-8B 和作者完整版 CSpider。模型是原始 BF16 权重，后续加载时才做 4-bit 量化。需固定模型提交时使用下载脚本的 `--revision`；训练和推理还会记录权重文件指纹。

CSpider 需要能够访问官方 Google Drive。无法访问时，按 [README.md](../README.md) 的方法获取并上传 `full_CSpider.zip`，再使用 `--cspider-archive`。不要以只含 JSON 的重打包数据代替完整版。

首轮可只用 CSpider。需要 SeSQL 时，在下载环境额外执行：

```bash
source .venv-download/bin/activate
python scripts/download_assets.py --only data --include-sesql --output-dir "$ASSETS_DIR"
deactivate
```

## 3．配置训练环境并清洗数据

下载与训练使用不同虚拟环境，避免 huggingface_hub 版本冲突。下例使用 CUDA 12.8 版 PyTorch 2.8.0，前提是服务器驱动兼容；其他 CUDA 构建按 [PyTorch 官方历史版本说明](https://pytorch.org/get-started/previous-versions/#v280)选择。

```bash
python3.11 -m venv .venv-train
source .venv-train/bin/activate
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements-train.txt
python -m pip check
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available()); assert torch.cuda.is_available()"
python -m unittest discover -s tests -v

python scripts/prepare_data.py --assets-dir "$ASSETS_DIR"
```

默认产生 `data/prepared/`。检查其中 `manifest.json` 和 `rejected.jsonl`：

- 原始数据只读，参考 SQL 必须能在对应物理 Schema 和 SQLite 上执行。
- 去除同库、同问题、同 SQL 的重复记录；不按 SQL 字符串跨库全局去重。
- 保持官方库划分。跨来源 Schema 冲突时保留测试优先、开发其次，隔离较低优先级记录。
- 超时、超行数、危险或无法执行的 SQL 被隔离。默认每条限时 2 秒、结果最多 10000 行。
- 执行成功只是必要检查，不能替代问题与答案的语义抽审。

如加入 SeSQL，使用新的 prepared 版本：

```bash
python scripts/prepare_data.py --assets-dir "$ASSETS_DIR" \
  --include-sesql --output-dir "$ASSETS_DIR/data/prepared-v2"
```

SeSQL 的 JSON 表内容会被重建为 SQLite；未引用的特殊表列名导致的错误会隔离，不自动修改标准答案。后续冻结命令需指向该新目录。

## 4．生成并抽审专项样本

```bash
python scripts/generate_special.py --assets-dir "$ASSETS_DIR"
```

输出 `data/special/`，包括字典标准化、指标公式变更、去重与比率、多表关联、时间与默认规则、澄清后补充、写入／危险函数／权限拒绝。默认 32／8／8 个训练、开发、测试数据库，每库 18 条样本。

这是虚拟业务模板种子数据。检查预期 SQL、澄清问题和拒绝原因，确认同一问题在不同规则下具有正确标签；后续仍需补充更多表达和独立构造的人工测试案例。模板测试结果不能替代真实业务验收。

如果第 3 步采用 `prepared-v2`，为上面的命令增加：

## 6．建立开发集基线，并预先确定验收阈值

```bash
python scripts/predict.py --model-dir "$ASSETS_DIR/models/Qwen3-8B" \
  --data-file "$ASSETS_DIR/data/sft-v1/dev.jsonl" \
  --output-file "$ASSETS_DIR/predictions/base-dev.jsonl"

python scripts/evaluate.py --assets-dir "$ASSETS_DIR" \
  --data-file "$ASSETS_DIR/data/sft-v1/dev.jsonl" \
  --predictions "$ASSETS_DIR/predictions/base-dev.jsonl" \
  --output-dir "$ASSETS_DIR/reports/base-dev"

cp configs/acceptance.example.json "$ASSETS_DIR/acceptance-v1.json"
```

根据开发集基线与项目目标，**在正式训练前**编辑 `acceptance-v1.json`，填写所有 `null`。配置含义：

| 配置 | 单位与含义 |
|---|---|
| `min_sql_gain_pp` | SQL 执行正确率至少提升多少个百分点；例如 3 表示 +3 个百分点 |
| `max_action_drop_pp` | action accuracy 最多下降多少个百分点；0 表示不允许下降 |
| `min_clarify_precision` / `min_clarify_recall` | 澄清行为选择的 precision/recall 下限，0～1 |
| `min_refuse_precision` / `min_refuse_recall` | 拒绝行为选择的 precision/recall 下限，0～1 |
| `max_unsafe_responses` | 应拒绝却输出 SQL 的最大条数 |
| `max_blocked_unsafe_sql` | 输出被执行安全检查阻止的 SQL 的最大条数 |

模板不擅自承诺绝对准确率。未填写的条件会得到 `pending`，不能判为通过。precision 无定义而对应条件已配置时，会判该项未通过。安全两类计数可能涉及同一条样本，不应相加当作唯一违规样本数。

填写完成后保留阈值文件与哈希，后续不得根据 test 成绩改阈值：

```bash
python -m json.tool "$ASSETS_DIR/acceptance-v1.json"
sha256sum "$ASSETS_DIR/acceptance-v1.json" > "$ASSETS_DIR/acceptance-v1.sha256"
```

程序会记录阈值哈希，但无法证明阈值选择的时间；该约定依赖实验记录。

## 7．确认训练脚本与监督约定

训练入口为 `scripts/train_qlora.py`。默认 QLoRA、micro-batch 1、梯度累积 16、总长 4096、rank 16、学习率 2e-4、2 epochs；这些是起跑配置。

输出协议统一为 JSON 三选一：

```json
{"action":"sql","sql":"SELECT ..."}
{"action":"clarify","question":"请提供起止日期。"}
{"action":"refuse","reason":"当前没有该表的访问权限。"}
```

训练与推理固定非思考模板，仅对回答计算损失。默认遇到超长样本停止；显式 `--drop-overlong` 才整条排除并记录，禁止静默截断 Schema 或标准 SQL。

## 8．短程试训和恢复检查

```bash
python scripts/train_qlora.py --model-dir "$ASSETS_DIR/models/Qwen3-8B" \
  --data-dir "$ASSETS_DIR/data/sft-v1" \
  --output-dir "$ASSETS_DIR/runs/smoke-v1" \
  --max-steps 4 --checkpoint-steps 2 --drop-overlong \
  2>&1 | tee "$ASSETS_DIR/logs/smoke-v1.log"

python scripts/train_qlora.py --model-dir "$ASSETS_DIR/models/Qwen3-8B" \
  --data-dir "$ASSETS_DIR/data/sft-v1" \
  --output-dir "$ASSETS_DIR/runs/smoke-v1" \
  --max-steps 4 --checkpoint-steps 2 --drop-overlong \
  --resume-from-checkpoint "$ASSETS_DIR/runs/smoke-v1/checkpoint-2" \
  2>&1 | tee "$ASSETS_DIR/logs/smoke-resume.log"
```

确认 loss 有限、GPU 不溢出、checkpoint 保存完整且能恢复，检查 `tokenization_report.json` 中超长样本数量、来源和复杂度。若调整长度、batch 或其他参数，使用新的 smoke 版本重新验证；恢复训练要求配置与数据保持一致。

## 10．最终测试、对比验收和交付

先根据 dev 选择并冻结最终 adapter，检查预先保存的阈值哈希，然后让基座和微调模型分别跑同一 test：

```bash
sha256sum -c "$ASSETS_DIR/acceptance-v1.sha256"

python scripts/predict.py --model-dir "$ASSETS_DIR/models/Qwen3-8B" \
  --data-file "$ASSETS_DIR/data/sft-v1/test.jsonl" \
  --output-file "$ASSETS_DIR/predictions/base-test.jsonl"

python scripts/predict.py --model-dir "$ASSETS_DIR/models/Qwen3-8B" \
  --adapter-dir "$ASSETS_DIR/runs/sft-v1/adapter" \
  --data-file "$ASSETS_DIR/data/sft-v1/test.jsonl" \
  --output-file "$ASSETS_DIR/predictions/sft-test.jsonl"

python scripts/evaluate.py --assets-dir "$ASSETS_DIR" \
  --data-file "$ASSETS_DIR/data/sft-v1/test.jsonl" \
  --predictions "$ASSETS_DIR/predictions/base-test.jsonl" \
  --output-dir "$ASSETS_DIR/reports/base-test"

python scripts/evaluate.py --assets-dir "$ASSETS_DIR" \
  --data-file "$ASSETS_DIR/data/sft-v1/test.jsonl" \
  --predictions "$ASSETS_DIR/predictions/sft-test.jsonl" \
  --output-dir "$ASSETS_DIR/reports/sft-test"

python scripts/compare_reports.py \
  --baseline-dir "$ASSETS_DIR/reports/base-test" \
  --finetuned-dir "$ASSETS_DIR/reports/sft-test" \
  --criteria "$ASSETS_DIR/acceptance-v1.json" \
  --training-metrics "$ASSETS_DIR/runs/sft-v1/train_results.json" \
  --output-dir "$ASSETS_DIR/reports/acceptance-v1"
```

### 对比的前置条件

- 两份报告均为完整覆盖的冻结 test，包含 SQL、clarify、refuse 三类样本。
- 测试数据、manifest、数据库哈希、SQLite／SQLGlot 版本、超时与评分代码一致。
- 同一底座权重和 tokenizer，基座报告未加载 adapter，候选报告加载了明确的 adapter。
- 系统提示、输入输出长度、量化精度、生成参数、推理代码、GPU 和推理依赖版本一致。
- 每条样本的 ID、来源、标签和预期行为一致，逐条明细未被改写。

条件不满足则拒绝比较，不创建“通过”报告。旧版缺少来源或运行信息的报告，需要使用当前版本重新推理和评测；不能靠手工补哈希冒充可比数据。不要用只处理 SQL 的 XiYan 子集作为此处的完整行为验收基线。

### 输出和退出码

`reports/acceptance-v1/` 包含：

- `comparison.md`：可直接阅读的总体指标、阈值检查、来源／标签分组、延迟与训练成本。
- `comparison.json`：机器可读结果，以及报告、阈值和可选训练指标哈希。
- `changes.jsonl`：逐条改善与回退 ID、来源、能力标签及错误信息。

退出码 `0` 表示自动检查通过；`1` 表示阈值未通过；`2` 表示条件待配置或输入不可比较。待配置会输出 pending 报告，输入不可比较则仅报错。输出目录已存在时拒绝覆盖。

报告中的 SQL／action 指标按当前自定义评分口径解释，不是官方 Spider 榜单分数。百分点变化与绝对准确率分开呈现。按来源和标签查看结果，避免整体提升掩盖局部回退。

延迟来自成功生成且记录了耗时的样本，展示 mean/p50/p95；训练成本可从 `train_results.json` 附加，缺省不编造。延迟是同一记录环境下的观察值，不是严格性能基准。当前配置没有把成本设为硬验收门槛。

自动通过之后仍需人工复核：指标分子分母和去重、澄清是否具体正确、空结果的偶然一致、安全边界，以及专项模板的代表性。复核记录随报告交付，不能用 action 命中率替代语义审核。

交付至少保留：最终 adapter 与 tokenizer、底座版本和指纹、`run_config.json`、`tokenization_report.json`、依赖文件、训练日志、冻结数据 manifest、阈值文件和哈希、test 预测及元信息、两份评测报告、对比报告、人工复核记录。生产 SQL 执行仍须独立的权限与只读控制。

## 11．首期结束后的评估

根据独立评测和错误分析决定是否开展 DPO 或 GRPO。当前不运行额外优化，也不把它们设为 SFT 无提升时的默认补救。

## 运行失败与验证边界

- 预测中断：相同命令加 `--resume`；损坏的半行 JSON、重复 ID 或配置变化会报错。`--limit` 仅用于冒烟测试，预测不完整不能通过最终验收。
- 训练中断：保持原参数，指定完整 checkpoint；没有有效 checkpoint 时保留失败目录并换新输出目录。
- 超长样本多：检查分布并重新规划长度与显存，不能无声丢弃复杂查询。
- 阈值未填：先完成正式训练前的指标约定，程序不会自动填一个“能通过”的数字。
- 本地验证覆盖数据／评测／验收逻辑、依赖解析和真实 tokenizer 模板；完整模型推理、CUDA 训练、峰值显存及 GPU 断点恢复仍需在实际云服务器验证。

各脚本参数和第 3～7 步细节另见 [训练运行说明.md](训练运行说明.md)。
