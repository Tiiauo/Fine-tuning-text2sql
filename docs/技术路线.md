# 问数模型微调技术路线

选型日期：2026-10-24。

## 1. 选定路线

Qwen/Qwen3-8B（非思考模式）→ 4-bit QLoRA 监督微调（SFT）→ 独立执行评测及行为评测 → 按错误类型补充数据并迭代 SFT。

首期训练方法固定为 SFT，不安排 DPO、GRPO 或全参数微调。QLoRA 是降低训练显存的方法，SFT 是学习目标，两者共同组成首期方案。选型依据是中文与指令处理需求、单卡 24GB 预算，以及当前尚无偏好对或经过验证的强化学习奖励环境；不代表已证明本模型在中文 SQL 上优于全部其他模型。

## 2. 项目范围与输入输出

- 训练通用 Text2SQL 能力，无需先建设真实业务数据库。
- 首期使用 SQLite 方言与公开样例数据库。其他方言属于后续明确扩展，不将 SQLite 结果宣称为多方言验收结果。
- 输入包含中文问题、方言、Schema、字段说明，以及该问题需要的字段值字典、指标定义、计算规则、允许访问的范围；涉及相对时间时提供时间基准。
- 输出采用统一 JSON，action 为 sql、clarify 或 refuse，对应 sql、question 或 reason 字段。SQL 行为只生成只读查询，训练、推理与评测使用相同协议。
- 检索模块不是本期实现对象；训练与评测直接提供上下文，并单独测试上下文缺失、歧义及无关候选信息。
- 无真实业务资料时，构造有明确虚拟字典和指标定义的样本，验收模型遵循给定规则的能力，不声称已掌握真实企业业务口径。

## 3. 数据路线与六项要求覆盖

首批以 CSpider 官方训练集为通用 SQL 主料，另建设规则清楚、可审核的专项样本。SeSQL 单轮补全版经格式适配、去重和执行验证后作为中文补充。BIRD filtered、SynSQL 和 CDC 180K 暂不进入首批，避免同时扩大清洗与适配范围。

| 原需求 | 数据构造方式 | 独立评测重点 |
|---|---|---|
| 业务问题到字段映射 | 中文问题配完整物理 Schema、字段说明；加入容易混淆的候选字段 | 表、字段和时间字段是否选对 |
| 字段值识别与标准化 | 在输入中显式提供别名与标准值字典；包括多个候选、无匹配值案例 | 标准值匹配；歧义时是否澄清；是否编造不存在的值 |
| 指标口径理解与计算 | 提供指标定义、分子分母、去重、粒度和时间规则；同一问题搭配不同定义 | 是否随定义改变 SQL，而非记忆固定公式 |
| 查询意图澄清 | 缺失会改变答案且无明确默认值的条件；完整问题；已有明确默认值的问题；澄清后补充信息的对话 | 应澄清时追问、信息充分时直接生成；补充后正确生成 |
| 多表关联与条件生成 | CSpider 多表查询，提供真实主外键；增加一对多重复计数等专项案例 | 关联路径、条件完整性、统计粒度和去重 |
| SQL 安全与方言适配 | SQLite 查询；给定权限范围的允许/拒绝案例；危险请求和诱导生成案例 | SQLite 可执行性、只读、权限遵循和拒绝行为 |

数据进入训练前检查：

1. 从原始 Schema 或数据库读取物理表列名、类型和主外键，确认目标 SQL 引用的对象确实存在。无法恢复正确上下文的样本剔除。
2. 通用 SQL 样本在对应样例库上验证；另审核问题与 SQL 是否语义一致。执行成功不能替代语义审核。
3. 保留数据来源和版本。Schema 标识包含来源，不能仅按不同数据集中的同名 db_id 合并。
4. 保留官方数据库划分，检查跨来源 Schema、SQL 模板和近重复问题。CSpider 与 Spider 的中英文对应样本不得跨训练和测试泄漏。
5. 专项合成样本同样按 Schema 分组隔离训练、开发和测试，人工审核标签；不将仅改写措辞的样本当作独立测试。
6. 使用原始数据发布条款，不把代码仓库许可证自动当作所有数据的许可证。

## 4. 模型、框架与算力

- 微调模型：Qwen/Qwen3-8B，训练与推理均固定非思考模板。
- 训练实现：在用户后续租用的 Linux GPU 云服务器上直接运行 Python 脚本，不使用 LlamaFactory。
- 技术栈：PyTorch、Transformers、PEFT、TRL；分别用于训练计算、模型与 tokenizer、QLoRA 适配参数以及 SFT 训练器，固定经短跑验证的版本和依赖。
- 数据处理、训练、推理与评测通过命令行脚本完成，支持保存和恢复训练检查点、导出 adapter，训练日志与产物保存在用户指定目录。
- 训练方式：4-bit QLoRA，仅更新 LoRA 适配参数。
- 单卡 24GB 试跑起点：micro-batch 1、梯度检查点、约 4096 token 总序列长度，再依据实际样本长度及峰值显存调整。
- 超长样本单独处理，不静默截断必需 Schema、规则或目标 SQL。长上下文可训练范围以实测为准。
- 学习率、LoRA rank、轮数等通过小规模开发集实验选择，选定后冻结；不在最终测试集上调参。
- 本地准备脚本与配置，训练和 GPU 兼容性验证在租用的云服务器上进行；服务器型号与 CUDA 环境确定后再固定依赖版本。

## 5. 训练与评测顺序

1. 建立数据清单、划分及可执行评测流程，先核验参考 SQL 与样例库的一致性。
2. 在冻结的开发集上评测原始 Qwen3-8B，并使用 XiYanSQL-QwenCoder-7B-2504 作现成 SQL 模型对照。分别保留各自要求的提示模板，使用相同问题、上下文和评分口径。
3. 用少量覆盖各类能力的样本完成显存、标签、模板和输出格式检查，再运行首轮 SFT。
4. 比较微调前后表现，按字段匹配、值匹配、口径、澄清、关联、安全分类分析错误。
5. 优先修复数据与补充对应样本，再做必要的 SFT 迭代。保留上一版检查点，避免专项改善伴随其他能力回退。
6. 在冻结的最终测试集上进行最终评测，形成模型产物与报告；模型选择和调参使用开发集。

评测口径：

- SQL：执行成功率、执行结果正确率，并对关联与指标专项做语义核验；结合输出列、重复值、排序要求和数值容差比较结果。
- 对空结果或数据分布导致的偶然一致案例，标记并补充核验；具备条件时使用多组测试数据，不能仅凭一次结果相同认定 SQL 等价。
- 澄清：该澄清时是否追问、不该澄清时是否直接回答，以及追问是否具体可回答。
- 规则遵循：别名映射、指标定义变更、默认值和权限范围的遵循情况。
- 安全：单独记录危险或越权输出；固定安全回归用例不允许出现违规 SQL。评测执行端使用只读、限时环境，不能依赖模型自行保证安全。
- 成本：峰值显存、训练耗时、生成长度及推理时延。

当前不凭空承诺绝对准确率。完成基线后、正式训练前冻结量化验收阈值；至少要求主要目标相对基线有可复核提升，澄清与安全满足约定门槛。小幅提升需要检查统计不确定性。

## 6. DPO 与强化学习的处理

两者均不属于首期必要交付，也不作为 SFT 无提升时的默认补救。

只有 SFT 后仍存在稳定可复现的错误，并能制作可靠的 chosen/rejected 对时，才另立小规模 DPO 对照实验。偏好对来自训练侧问题及经过验证的模型候选，不使用最终测试数据，不把等价 SQL 标为负例。

只有具备可靠执行奖励及额外采样预算时，才评估 GRPO/RLVR。每种新增方法都从明确的 SFT 检查点出发，对比独立开发集收益、回退与成本，再决定是否纳入后续路线。
